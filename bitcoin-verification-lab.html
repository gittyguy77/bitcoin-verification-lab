The 21 Million Supply Cap

"There will only ever be 21 million bitcoin"
✓

This is the most important claim — and the easiest to verify! The limit isn't a promise; it's written directly in Bitcoin's source code, enforced by every single computer running the Bitcoin software.

📟 The Actual Bitcoin Code

This is real C++ code from Bitcoin Core. Every line is public. Anyone can read it.

CAmount GetBlockSubsidy(int nHeight, const Consensus::Params& consensusParams) { // How many halvings have happened so far? int halvings = nHeight / 210000; // ← 210,000 blocks = ~4 years // Safety: if halvings goes over 64, reward = 0 if (halvings >= 64) return 0; // Start at 50 BTC per block CAmount nSubsidy = 50 * COIN; // ← 5,000,000,000 satoshis // The magic line: cut the subsidy in half for each halving nSubsidy >>= halvings; // ← "shift right" = divide by 2 each time return nSubsidy; }

Key Line nSubsidy >>= halvings means: "Start at 50 BTC, then cut in half every 210,000 blocks"

The Result If you add up all the block rewards after 32 halvings, the total ≈ 20,999,999.9769 BTC. The code implicitly creates a 21M cap through the halving math — there is no literal MAX=21000000 line, but the exponential decay mathematically guarantees it can never exceed ~21M.

Enforcement Every node checks every block. If a miner tried to mint more than allowed, the block would be immediately rejected by the entire network.

Immutability — The Block Chain

"Once a transaction is confirmed, it cannot be changed or reversed"
✓

Each block links to the previous one using a cryptographic fingerprint called a hash. If you change anything in a block — even one character — its hash changes, breaking the chain. This makes tampering instantly detectable.

🧪 Try to Hack the Blockchain

Click "Try to Hack" on Block #2 — we'll simulate changing a transaction. Watch what happens to every subsequent block.

✅ Blockchain intact — all hashes linked properly

Why It Works Each block header contains hashPrevBlock — the hash of the previous block. This creates an unbreakable chain: you'd have to re-mine every single block from the point of change onward, and do it faster than the entire Bitcoin network. That's computationally impossible after just a few confirmations.

Avalanche Effect Changing one bit in a block produces a completely different hash. There's no way to "predict" or "control" what the new hash will be — it's all or nothing.

✅ How to Verify This Yourself

  1. Use a block explorer like mempool.space.
  2. Click any block and find the "Previous Block Hash" field.
  3. Copy the previous hash and search for it — it will match the actual previous block's hash.
  4. Try this for 5 blocks in a row — every single one chains to the previous. There's no gap, no break.
  5. Deep verification: Run a full node. Your node independently validates every block and every hash from the genesis block in 2009 to today.

How It Works Bitcoin uses a peer-to-peer network. When you send bitcoin, your transaction broadcasts to every node. Each node independently validates it against the same rules. There's no central server that says "yes" or "no."

The "Attack" Test If any government tried to shut Bitcoin down, they'd need to find and shut down thousands of independently operated nodes in 100+ countries — many running on Tor, in data centers, basements, and laptops. There's no single building to raid.

Fun fact: You can run a Bitcoin node on a Raspberry Pi ($35 computer) from your living room. If you do, you're a global peer.

Difficulty Adjustment — Self-Balancing

"Bitcoin automatically adjusts mining difficulty to keep blocks at 10 minutes"
✓

This is one of Bitcoin's most ingenious features. Every 2,016 blocks (~2 weeks), every node checks: "Were the last 2,016 blocks found faster or slower than 10 minutes each?" If faster, mining gets harder. If slower, it gets easier. The network self-balances automatically.

The Actual Code In src/pow.cpp, the GetNextWorkRequired() function calculates the new difficulty. The maximum adjustment per cycle is ±400% (4× easier or harder) to prevent wild swings. The code is ~60 lines — any programmer can audit it.

Why It Matters Without difficulty adjustment, miners would find blocks in seconds when price is high (instability) or take days when price is low (transactions never confirm). The adjustment keeps Bitcoin running smoothly whether 10 miners or 10 million.

✅ How to Verify This Yourself

  2. Look at the history: Scroll back years — difficulty has gone up and down as miners joined and left. The network never broke.
  3. Watch the countdown: The next adjustment is always visible — every 2,016 blocks, like clockwork.
  4. Code verification: The adjustment code is at github.com/bitcoin/bitcoin/src/pow.cpp. You can read every line.

Seed Phrase Security — Impossible to Guess

"Your 12-word seed phrase cannot be brute-forced, even by all computers in the universe"
✓

This sounds unbelievable, but the math is undeniable. A 12-word BIP39 seed phrase uses 2048 possible words chosen at random. That gives 2048¹² combinations — a number so astronomically large it defeats every computer that could ever exist.

🧮 The Numbers Are Mind-Boggling

340,282,366,920,938,463,463,374,607,431,768,211,456

= 2¹²⁸ combinations for a 12-word seed

  • 5.4 × 10³⁹ — 12-word seed combinations (2048¹²)
  • 7.5 × 10¹⁸ — Grains of sand on Earth
  • 10⁵⁰ — Atoms on Earth
  • 🌍 If you checked 1 billion seeds per second since the Big Bang (13.8B years ago), you'd have checked 0.0000000001% of all possible 12-word seeds.
  • 🪐 A 24-word seed (2²⁵⁶) has more combinations than there are atoms in the observable universe — by many orders of magnitude.

The BIP39 Standard Bitcoin Improvement Proposal 39 defines a list of 2,048 words (see english.txt on GitHub). A 12-word phrase = 128 bits of entropy (with 4 checksum bits). A 24-word phrase = 256 bits of entropy.

⚠️ The REAL Danger The math is unbreakable — but humans break their own security by: taking photos of their seed, typing it online, using phishing sites, or generating seeds with bad random number generators. The system is secure. The user is the weakest link.

✅ How to Verify This Yourself

  1. See the word list: Go to github.com/bitcoin/bips/bip-0039/english.txt — 2,048 words.
  2. Do the math: 2,04812 = 5.4 × 10³⁹. Type "2048^12" into Google — it computes it instantly.
  3. Understand the scale: There are "only" 10⁸⁰ atoms in the observable universe. 2,04812 is huge, but 2,04824 is larger than 10⁸⁰.
  4. Check the BIP: Read BIP39 specification — it's a short, readable document.

The Halving Schedule — Predictable Supply

"New bitcoin creation is cut in half every 4 years, predictably, until ~2140"
✓

Every 210,000 blocks (~4 years), the reward for mining a block is cut in half. This is hard-coded, not voted on. It will happen whether you want it to or not, until the subsidy reaches zero around 2140.

  3. Read the code: The line consensusParams.nSubsidyHalvingInterval = 210000 is in the public Bitcoin Core source code.
  4. Run your own node: It enforces this rule independently — no one can change it on your node without your permission.

Open Source — Anyone Can Read Every Line

"Bitcoin's code is completely open source. Anyone can review it for backdoors or hidden features"
✓

Bitcoin's code isn't secret — it's open source under the MIT license. Bitcoin Core, the reference implementation, has been reviewed by thousands of developers, security researchers, and academics over 16+ years. There are no hidden backdoors, no secret inflation, no "hidden mint" button.

What "Open Source" Means The MIT license says: anyone can copy, modify, and distribute the software. There is no company behind it. If tomorrow someone added a backdoor to Bitcoin Core, every node operator would see the change in the code and reject it — or simply refuse to upgrade.

The Social Contract Because thousands of eyes review every code change, introducing a hidden feature (like printing more bitcoin) is essentially impossible. The consensus rules are the constitution, and every node is a citizen that enforces them.

Bitcoin ≠ Bitcoin Core There are multiple independent implementations of the Bitcoin protocol: Bitcoin Core (C++), btcd (Go), and others. They all enforce the same consensus rules. If one implementation had a bug, the others would reject it. This is redundancy by design.

⚠️ Note on Bitcoin Knots: The latest version of Bitcoin Knots (29.4+) follows the BIP-110 / RDTS fork, not the main Bitcoin chain. However, the pre-RDTS version (v29.3.knots20260507) still follows the main chain — some users prefer it. Always verify which chain a client follows before running it. More context on the fork →

  1. Go to GitHub: github.com/bitcoin/bitcoin — no account needed to browse.
  2. Browse the code: Click into src/, then consensus/, then validation.cpp. Read the functions.
  3. Check the commit history: See every change ever made to Bitcoin Core — who made it, when, and why.
  4. Look at the issues: See real bug reports and discussions from the community.
  5. Check for alternative clients: Search for "btcd" — an independent full node implementation written in Go.

Censorship Resistance — No One Can Freeze You

"No government, bank, or company can block or reverse a Bitcoin transaction"
✓

This is the superpower that makes Bitcoin different from every digital payment system before it. Once a transaction is confirmed by the network, no one on Earth can reverse it. No CEO, no court order, no government decree. The math decides, not people.

🧪 How Censorship Resistance Works

✅ What Bitcoin CAN Do

  • ✔ Send money to anyone, anywhere, anytime
  • ✔ Receive money without asking permission
  • ✔ Hold your own keys (be your own bank)
  • ✔ Send as little as 0.00000001 BTC (~$0.001)
  • ✔ Transact on a Sunday. Or Christmas. Or during a bank holiday.

❌ What Bitcoin CANNOT Do (This Is Good)

  • ✖ Freeze your account
  • ✖ Reverse a confirmed transaction
  • ✖ Block a valid transaction from being mined
  • ✖ Create new coins from nothing
  • ✖ Charge you fees without your consent

Why It Works Every node validates every transaction independently. A transaction that pays the right fees, has valid signatures, and spends unspent outputs will be accepted by the network regardless of who you are. The nodes don't know your name, your nationality, or your politics — they only check math.

The 51% Attack Technically, if a group controlled >50% of mining power, they could temporarily reverse recent transactions. This is called a 51% attack. But they can't: (a) create new coins out of thin air, (b) change the rules permanently, or (c) spend your coins without your keys. And recovering from one is just a matter of other miners joining honest mining.

⚡ Lightning Network For small everyday payments, the Lightning Network adds another layer: instant, near-zero fee transactions with the same censorship-resistant properties.

✅ How to Verify This Yourself

  1. Send a transaction: Use any wallet. Send $1 to a friend. It goes through — no approval needed.
  2. Check a block explorer: Go to mempool.space, search for a recent transaction. It's there for everyone to see — no one deleted it.
  3. Run a node: When you run a full node, you decide which transactions to accept. If someone tried to force an invalid transaction, your node would reject it — and there's nothing they can do about it.
  4. Read about real examples: WikiLeaks (2010), the Canadian trucker protests (2022) — Bitcoin donations received and spent despite government pressure on banks.

Bitcoin as Sound Money

"Bitcoin is better money than gold, fiat, or any alternative humanity has tried"
✓

Money isn't just "what we use to buy things" — it's a technology that evolved over thousands of years. Before you can judge Bitcoin as money, you need to know what makes money good. Economists have identified 7 essential properties. Let's compare Bitcoin, gold, and fiat across all of them.

🔍 Explore Each Property

Click a property to see how each form of money compares:

🏔️ Scarcity — "Is there a hard limit?"

Good money can't be printed into oblivion. The rarer something is, the better it holds its value.

₿ Bitcoin
🟢 Mathematically capped at 21M. Verifiable in code. No human can change it without every node agreeing.
🥇 Gold
🔵 Hard to find, but new gold is mined every year (~3,500 tons/yr). Supply grows ~1-2% annually. We don't know how much is left.
💵 Fiat
🔴 Infinite. Central banks can print unlimited amounts. In 2020-2023, the US money supply grew ~40%. No cap, no limit.

🧱 Durability — "Does it last?"

Money shouldn't rot, rust, or degrade over time. If it decays, it's a bad store of value.

₿ Bitcoin
🟢 Purely digital information. Cannot rot, rust, or be physically destroyed. Lasts as long as the internet exists.
🥇 Gold
🟢 Virtually indestructible. Gold from 3,000+ years ago is still perfectly preserved. Doesn't corrode or tarnish.
💵 Fiat
🔴 Paper bills wear out (average lifespan of a $1 bill: ~6.5 years). Must be constantly replaced. Digital fiat is just a ledger entry — deleteable.

✈️ Portability — "Can I move it?"

Can you take it with you? Can you send it across the world?

₿ Bitcoin
🟢 Send any amount, anywhere, instantly. A $1B transaction moves as easily as $1. No borders, no gates, no permission needed.
🥇 Gold
🔴 Heavy and expensive to move. Transporting large amounts requires armored vehicles, insurance, and trust. Moving $1M in gold weighs ~55 lbs.
💵 Fiat
🟠 Digital transfers are easy, but banks can block them, governments can freeze them, and international wires take days. Physical cash is bulky.

🔪 Divisibility — "Can I split it?"

Good money can be divided into small units for small purchases.

₿ Bitcoin
🟢 Divisible to 8 decimal places (1 sat = 0.00000001 BTC). Can send fractions of a cent. Future: divisible even further if needed.
🥇 Gold
🔴 Can be split, but it requires melting and assaying. Tiny amounts are impractical — you can't buy a coffee with gold dust.
💵 Fiat
🟠 Divisible to 2 decimal places usually. Digital can go further but physical coins have practical limits. Inflation eats the smallest denominations.

🔄 Fungibility — "Are all units equal?"

One unit should be perfectly interchangeable with another. You shouldn't discriminate between different coins.

₿ Bitcoin
🔵 Mostly fungible — 1 BTC = 1 BTC. However, coins can be "tainted" on the blockchain (tracked from illicit activity). Some exchanges blacklist certain coins.
🥇 Gold
🟢 One ounce of pure gold = another ounce of pure gold. No one tracks "history" of a gold bar. Complete fungibility.
💵 Fiat
🟠 Digital dollars are tracked. Banks can freeze specific accounts or reject specific transactions. "Tainted" bills are legally seized.

👀 Recognizability — "Is it easy to verify?"

Can the average person tell real from fake without special equipment?

₿ Bitcoin
🔵 Easy to verify digitally. Any wallet checks the blockchain. Public-key cryptography means faking a valid transaction is computationally impossible. However, it's a learning curve.
🥇 Gold
🟠 Counterfeit gold exists (tungsten cores, plated bars). Verifying purity requires density tests, acid tests, or XRF analyzers. Hard for average person.
💵 Fiat
🟢 Highly recognizable. Holograms, watermarks, security threads. Governments invest billions in anti-counterfeiting. However, digital fiat in a bank account is just a number you trust.

🏛️ Store of Value — "Does my purchasing power hold?"

The most important property over time — can I save in it and not lose value?

₿ Bitcoin
🟢 Perfect supply schedule. Zero inflation (once fully mined). Has appreciated against every fiat currency since inception. Volatile in the short term, but the trend over any 4+ year window is up.
🥇 Gold
🔵 Held value for thousands of years. An ounce of gold bought a fine toga in Rome (~300 AD) and buys a fine suit today. ~1-2% annual supply inflation.
💵 Fiat
🔴 Since 1971 (Nixon ended gold convertibility), the US dollar has lost ~87% of its purchasing power. By design — central banks target 2% inflation, meaning your savings lose half their value every ~35 years.

⏳ The History of Money: Why It Matters

🐚 Barter → Cowrie Shells (10,000 BC) — Direct trade was inefficient. Shells became first widely used currency.
🥇 Gold & Silver Coins (600 BC) — Durable, divisible, scarce. The gold standard prevailed for ~2,600 years.
📄 Paper Money (Gold-Backed) (1600s) — Receipts for gold. Then governments slowly detached from gold...
💸 Pure Fiat (1971 — today) — "Nothing backs it but government decree." Since then: 87% dollar devaluation, endless printing, boom-bust cycles.
₿ Bitcoin (2009 — today) — First money with mathematically provable scarcity. No issuer. No borders. No inflation. The natural next step in monetary evolution.

Consensus & Policy Rules — How Bitcoin Changes (And Doesn't)

"No single person, company, or government can change Bitcoin's rules. Changes require near-universal agreement"
✓

You've heard it before: "Bitcoin is hard to change. No government can change the rules." But why? The answer is in how Bitcoin distinguishes between two kinds of rules — and who gets a say when a change is proposed.

⚖️ Two Kinds of Rules

🔒 Consensus

Hard-coded in the protocol. Every single node enforces them on every block. Non-negotiable.

✅ 21M supply cap
✅ 10-min block target
✅ Subsidy halves every 210k blocks
✅ Difficulty adjustment
✅ Signature verification
❌ Blocks violating these = immediately rejected
⚙️ Policy

Local preferences set by each node operator. Configurable. Every node can choose differently.

📏 Min tx relay fee
📏 Max tx size
📏 Standard script types
📏 Block size relay limit
One node's policy isn't another's

What This Means A valid block must pass every consensus rule on every node. Policy rules only affect what a node relays in its mempool — not what blocks it accepts. This distinction is why individual nodes have freedom without breaking the network.

📜 How Changes Happen — BIPs

Bitcoin Improvement Proposals (BIPs) are the process for suggesting changes. Anyone can write one — it's a public document reviewed by the community.

✏️ Draft
Idea proposed on GitHub
→
💬 Review
Community discussion & refinement
→
🟢 Activation
Miners signal + nodes adopt

Soft Fork Tightens the rules. Old nodes still see new blocks as valid (they're just less strict). Example: SegWit (2017). Requires majority miner support.

Hard Fork Changes the rules in a way old nodes can't follow. Requires near-universal upgrade. Example: Bitcoin Cash split (2017) — those who didn't upgrade ended up on a different chain.

🛡️ Why Bitcoin Is Resilient to Change

👑
Node Sovereignty
Every node operator chooses which software to run. No one can force an upgrade on you.
👥
Economic Majority
Miners + developers can propose changes, but only node operators (users) have final authority.
🤝
Social Consensus
No formal governance. Change is slow by design — this prevents capture but requires near-universal buy-in.

📖 Real example — 2017: Bitcoin Cash had miner, developer, and exchange support. But enough node operators chose not to upgrade that the original chain remained Bitcoin. The community decided.

✅ How to Verify This Yourself

  1. Browse every BIP ever proposed: Visit github.com/bitcoin/bips — no account needed. See the full list of proposals, including which were accepted and which were rejected.
  2. Read BIP 1: It defines the BIP process itself. Anyone can propose a change — but adoption is never guaranteed.
  3. Check your node's config: If you run Bitcoin Core, open your bitcoin.conf file. These are your policy rules. You can change them. Consensus rules cannot be changed without upgrading your software.
  4. Search "Bitcoin Core release notes": See what changes were actually activated and how long each took from proposal to activation (many take years).
  5. Read about the 2017 split: Search "Bitcoin Cash fork explained" — see how the community handled a disagreement without a central authority.

Proof of Work — Energy as the Foundation of Trust

"Miners must spend real energy to create blocks. This energy cost is what makes Bitcoin trustless and secure"
✓

This is the single most important innovation in Bitcoin — the thing that makes everything else possible. Proof of Work (PoW) is what allows thousands of strangers to agree on the state of the ledger without trusting anyone.

🔨 How Proof of Work Works

Miners compete to find a number (a "nonce") that, when hashed with the block data, produces a result below a target. The first to find it wins the right to propose the next block and earn the block subsidy.

// Simplified: miners try different nonces until: SHA256("block data" + nonce) < target // There's no shortcut — it's pure brute force. That's the "work."

Why Energy Matters Making block production expensive is the entire point. If creating a block cost nothing, attackers could flood the network with fake blocks at no cost. The energy cost is what makes attacking Bitcoin more expensive than playing by the rules.

The Whitepaper Satoshi described it as "one-CPU-one-vote." The node with the most computational power gets the deciding vote — not the richest person, not the biggest company. Energy is the decoupling mechanism that separates power from wealth and political influence.

💰 Why This Makes Bitcoin Valuable

Every bitcoin that gets mined required real energy to produce. This creates a cost basis — a floor below which miners won't sell. Unlike fiat (printed at zero cost) or most altcoins (pre-mined at zero cost), the supply of new bitcoin is always tied to real-world energy expenditure.

₿ Bitcoin
Each coin required real energy to produce. The cost to attack = buy more hardware + energy than all honest miners combined.
🔷 Proof of Stake
Validators post a bond of coins. No energy cost to create blocks. Attackers with enough coins can rewrite history at no energy cost. "Nothing at stake" problem.
💵 Fiat
Created at zero marginal cost. Central banks can print unlimited amounts. No cost basis — just political will.
🌍 Energy as a feature, not a bug: Bitcoin incentivizes miners to find the cheapest energy on earth — often stranded or curtailed energy that would otherwise be wasted. Far from being "waste," Bitcoin turns otherwise useless energy into the most secure financial settlement network in history.

✅ How to Verify This Yourself

  1. See live network hash rate: Visit mempool.space and scroll to the hash rate chart. Watch it grow over time — more energy = more security.
  2. Read the code: The PoW validation is in pow.cpp in Bitcoin Core. Every node independently checks that the block's hash meets the target.
  3. Run a node: Your node independently validates every block's proof of work — no trust required, just verification.
  4. Compare: Search "proof of stake vs proof of work" and evaluate the security arguments on both sides honestly.
